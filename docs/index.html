MLOps de production · Mobilité urbaine · Métropole de Lyon

La mobilité lyonnaise prédite à une heure.

LyonFlow collecte neuf flux open data (boucles de comptage, bus TCL, Vélo'v, météo, chantiers…) toutes les 5 minutes. Il les raffine en couches Bronze → Silver → Gold dans PostgreSQL, prédit la vitesse du trafic et la disponibilité Vélo'v à H+1h avec XGBoost, puis restitue le tout dans une application pensée pour trois publics : l'usager, l'opérateur TCL et l'élu.

Le besoin

Des données publiques abondantes, mais personne ne les croise

Ce que publie la Métropole

  • Vitesses mesurées par les boucles de comptage
  • Positions des bus TCL (SIRI Lite)
  • Stations Vélo'v (GBFS), météo, qualité de l'air, chantiers

Les questions sans réponse

  • Usager : voiture, bus ou vélo, maintenant ?
  • Opérateur TCL : où le réseau décroche-t-il ?
  • Élu : ce retard de bus est-il opérationnel, ou faut-il une voie dédiée ?

Ce que fait LyonFlow

  • Collecte et historise chaque flux, sans le modifier
  • Prédit vitesse et Vélo'v à H+1h, avec intervalle P10–P90
  • Croise retard bus et congestion (gold.mv_bus_traffic_spatial, jointure à 100 m)

L'application lancée sur la machine de test

Ces captures viennent du code du dépôt, lancé localement (Ryzen 9 3900X, Windows 11, Python 3.12). Pas à pas

Du capteur à la décision, en sept étapes

Collecter

Airflow interroge les sources ouvertes selon leur rythme : toutes les 5 minutes pour le trafic, les bus et les Vélo'v, toutes les 15 minutes pour TomTom, toutes les 6 heures pour la vigilance météo.

Fichier
dags/bronze/collect_bronze.py
Pourquoi
Une source qui tombe ne bloque pas les autres : chaque collecteur échoue isolément.

Bronze : tout garder, brut

Les réponses JSON sont stockées telles quelles (JSONB), sans transformation.

Pourquoi
On peut toujours rejouer l'historique si une règle de nettoyage change.

Silver : nettoyer

Dédoublonnage (DISTINCT ON), parsing SIRI, reprojection géographique (4326 / 2154), filtrage des capteurs défaillants.

Cadence
transform_bronze_to_silver, toutes les 5 min (décalé de 2 min)

Gold : préparer pour le ML et le métier

Features : vitesse courante, retards à 5/10/15 min, moyenne glissante, heure encodée en sinus/cosinus, météo, vacances, jours fériés. Vues matérialisées : goulots, retards par tronçon.

Fichier
src/models/xgboost_speed.py (11 features)

Prédire

XGBoost entraîne trois modèles quantiles (P10, P50, P90). La médiane sert de prédiction, P10 et P90 forment l'intervalle de confiance. Entraînement chaque nuit à 03:38, inférence toutes les 15 minutes.

Pourquoi
Un usager comprend « entre 38 et 51 km/h » mieux qu'une valeur unique faussement précise.

Surveiller

Chaque matin à 05:30, un rapport de dérive (PSI) compare les erreurs du modèle aux vitesses TomTom de la veille et le publie dans gold.model_drift_reports, affiché aux personas.

Seuils
< 0,1 stable · 0,1–0,2 modéré · > 0,2 dérive significative

Restituer

FastAPI sert les prédictions. Streamlit les met en scène : 18 pages (16 par persona, plus RGPD et À propos) et un rapport PDF pour les élus.

À lire avant de citer la précision

Le jeu synthétique sert à mesurer le coût du modèle (temps, taille), pas sa qualité : une MAE sur des données inventées ne voudrait rien dire. Les métriques de précision du projet (MAE 5,8 → 3,2 en séparant trois modèles, benchmark MAE 6,97 / R² 0,71) proviennent du dépôt de travail et du serveur de production. Elles n'ont pas pu être revérifiées ici.

# src/monitoring/psi.py — dérive PSI robuste, sans dépendance lourde
def _safe_psi_term(pct_ref: float, pct_curr: float, eps: float = 1e-6) -> float:
    if pct_ref < eps and pct_curr < eps:
        return 0.0
    if pct_curr < eps:
        pct_curr = eps
    if pct_ref < eps:
        pct_ref = eps
    return (pct_curr - pct_ref) * np.log(pct_curr / pct_ref)
Journal

La remise en route, dans l'ordre

Ce qui a été fait, y compris les surprises.

Analyse

Quelle version tourne sur la machine ?

Les conteneurs lyonflow-* de Docker Desktop ne viennent pas de ce dépôt. Ils viennent d'un autre projet LyonFlow (prototype ST-GRU-GNN avec Ray et Optuna, 2 DAGs, PostgreSQL 15 sans PostGIS, registre MLflow vide). Ce dépôt-ci (pgRouting, 27 DAGs, MinIO) n'y tourne pas. Toutes les vérifications ont donc été faites sur le code de lyonflowfull, lancé localement.

Tests

Suite pytest complète

Premier passage : 649 verts, 1 rouge. Le test lisait un fichier source sans préciser l'encodage : il passe sous Linux ou macOS, échoue sous Windows (cp1252).

Correctif · tests

Encodage explicite

encoding="utf-8" ajouté dans deux tests (test_real_durations.py, test_audit_sprint22.py). Résultat : 650 / 650.

Mesure

Coût du modèle et calibrage du PSI

Sans données de production, la vraie classe de modèle a été mesurée sur un jeu synthétique. Le PSI a été soumis à des décalages connus : il reste « stable » à +0,25 σ et bascule en « dérive significative » à +0,5 σ.

Correctif · dashboard

La page « Statut du service » plantait

Base injoignable, la page censée dire si le service va bien affichait une trace Python. Les trois autres voyants savaient déjà passer en « Indéterminé ». Le voyant Alertes et le journal des incidents suivent maintenant la même règle.

Vérification

Recoupement avec la fiche portfolio

27 DAGs et 7 groupes d'alertes Prometheus : confirmés. 620 tests : il y en a désormais 674. « Réentraînement toutes les 30 min » : inexact, la vitesse est réentraînée chaque nuit (le DAG horaire est en pause depuis juillet) et Vélo'v chaque heure.

Livraison

Kubernetes réveillé

La branche kubernetes (juin 2026) ne se construisait plus et visait encore le GNN et Redis, retirés depuis. Elle est réalignée en deploy/k8s et validée par kubectl kustomize.

Cible de déploiement

Du VPS unique au cluster

La production tourne aujourd'hui en Docker Compose sur un seul serveur (déploiement et retour arrière scriptés, sauvegarde nocturne). Pour passer à l'échelle et à la haute disponibilité, deploy/k8s fournit une base kustomize et deux overlays.

Les pièces

  • StatefulSet postgres : image pgRouting 16-3.5-3.7.3 (PostGIS seul casserait le routage)
  • Deployments fastapi / streamlit : HPA, PodDisruptionBudget, sondes de vie
  • MLflow 2.12.1 : backend Postgres, PVC d'artefacts
  • CronJob pg_dump quotidien, 7 copies
  • Airflow via le chart Helm officiel, git-sync des DAGs
  • Monitoring en composant (ServiceMonitor, règles), activé en prod
